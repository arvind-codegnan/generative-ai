# Contributing

Contributions should strengthen explanation, classroom usability, correctness, or assessment quality.

## Content rules

- Keep the target audience at Java fresher level.
- Explain every design with Core Java types and standard-library concepts.
- Do not add Spring, Jakarta framework, or container-managed abstractions.
- Use Java 21 language features only when they clarify the design.
- Mark every snippet as a concept fragment, boundary sketch, configuration excerpt, or anti-pattern.
- Do not add runnable applications, API keys, real customer data, or complete assignment solutions.
- Prefer Mermaid diagrams that GitHub can render directly.
- Add an answer rationale for each new objective question.
- Cite primary documentation for version-sensitive technical claims.

## Review checklist

- Does the content distinguish deterministic Java code from probabilistic model output?
- Is input/output validation visible at the boundary?
- Are security, privacy, evaluation, cost, and failure paths addressed?
- Does the assignment require thinking rather than transcription?
- Is terminology consistent with the glossary?
